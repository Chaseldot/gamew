# 05 Identity and Archetypes — Build Presentation Layer

日期：2026-04-24  
状态：iteration scaffold  
Owner：canon systems designer

## Purpose
本文件定义“出身 / 身份”和“角色形象（捏脸及 NPC）”如何接入武侠 build 系统。

核心原则：**职业名不是系统根节点**。玩家熟悉的武侠幻想应由流派、传承、旁修、出身 / 身份、角色形象组合出来，而不是先选择一个固定职业。

## Layer boundaries

### 出身 / 身份
出身 / 身份负责叙事与社会位置，不负责替代战斗职业。

可承载：
- 开局资源、初始关系、声望偏置；
- 对话、门派、官府、江湖势力反应；
- 剧情钩子与身份冲突；
- 少量起步便利或推荐 build。

不得承载：
- 锁死唯一流派；
- 锁死唯一传承；
- 提供无法由战斗系统解释的职业特权；
- 把身份奖励做成必选数值税。

示例身份：
- **僧人**：戒律、寺院关系、清修声望、武僧幻想入口。
- **捕快**：官府权限、缉捕线索、江湖合法性压力。
- **医谷**：医术声望、药材渠道、救人与毒术的道德张力。
- **杀手楼**：暗线委托、仇家、隐秘身份、背叛风险。
- **门派弟子**：师承关系、门规、同门网络、门派冲突。

### 角色形象（捏脸及 NPC）
角色形象负责让玩家和 NPC 被一眼理解。

可承载：
- 捏脸 / 服饰 / 姿态 / 武器展示预设；
- NPC 模板；
- 推荐 build 标签；
- 剧情称谓与江湖传闻。

不得承载：
- 唯一职业规则；
- 无法替换的核心数值；
- 传承成立前提。

## Archetype build grammar

每个熟悉幻想都应写成：

```text
角色形象 = 流派主轴 + 传承倾向 + 旁修工具 + 出身 / 身份 + 表现标签
```

示例：

| 角色形象 | 可行组合方向 | 设计含义 |
|---|---|---|
| 武僧 | 拳掌 / 稳守型传承 + 僧人身份 + 少量医 / 心法旁修 | “武僧”是结果，不是固定职业。也可以有破军武僧或游锋武僧。 |
| 游侠 | 游锋主轴 + 江湖散人 / 门派弟子身份 + 轻功或暗器旁修 | 强调行走江湖、机动、义气与探索。 |
| 毒医 | 药 / 毒相关旁修 + 医谷身份 + 任一主修承载战斗主轴 | 毒医不应强制等于某一流派；战斗主轴可不同。 |
| 机关师 | 机关旁修 + 门派 / 工匠关系 + 控场或布置型传承 | 机关是横向工具，不取代主修闭环。 |
| 琴魔 | 音律 / 心神相关工具 + 高压传承 + 孤绝形象 | “魔”来自表现与代价，不要求高魔解释。 |
| 侠盗 | 游锋或轻身主轴 + 捕快 / 杀手楼 / 江湖身份冲突 + 潜行工具 | 侠盗是社会身份与行为方式的组合。 |

## Wuxia fan loop input format

武侠幻想 reviewer 提出幻想时必须输出：
1. 幻想名；
2. 期望玩家感受；
3. 需要哪些层级表达；
4. 当前系统缺口；
5. 建议 ticket；
6. 通过条件；
7. 优先级。

不得只提出“我想要某某职业”。必须反推它由哪些层级组合达成。

## Exit condition for archetype loop
角色形象 loop 在以下条件同时成立时停止：
1. 核心样例（武僧、游侠、毒医、机关师、琴魔、侠盗）都能由多层组合表达；
2. 没有样例要求新增职业根节点；
3. 没有样例强制某个旁修成为 mandatory tax；
4. CRPG reviewer 判定这些组合有战术选择与 counterplay；
5. leader 接受当前版本进入下一阶段。
