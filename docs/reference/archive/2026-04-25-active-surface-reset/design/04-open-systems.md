# 04 待完成系统

状态：active 待设计队列
用途：记录资源重构后仍未完成、应进入下一轮工作流的系统。

## 为什么需要本文件

当前重构基线已经定义了流派身份、传承身份、精修、旁修深度、幻想测试和边界。但这些还不足以让构筑系统进入可执行层。

本文件列出未完成系统，让下一阶段设计可以从清楚的队列开始，而不是回 archive 翻旧报告。

## 最高优先级：Loadout

当前基线多次提到 loadout、经脉槽和槽位压力，但尚未定义具体规则。

仍未解决：

- 角色可以携带多少主动武学 / 招式 / 方法。
- 主修、传承、精修、旁修是否消耗同一种预算。
- 旁修 1 / 2 / 3 解锁的是被动标签、主动动作、反应钩子，还是完整动作链。
- 技法、被动、装备绑定招式、经脉 / 运功是否使用不同槽位。
- 伞、扇、手杖、软兵、飞刀、飞针、乐器、机关、符器等可见道具如何与技能装配互动。
- loadout 在战斗外、休息时、升级时如何调整。
- 如何制造机会成本，又不让混修显得被惩罚。

需要产出的设计：

- 槽位模型。
- 携带 / 装配模型。
- 能表达纯主修、单旁修、双旁修的规则。
- 当某个 build 只有在过宽松槽位假设下才成立时，如何判定失败。

## 经脉 / 运功位

旧基线使用了相关占位词，但没有定数量、功能或解锁节奏。

仍未解决：

- 经脉槽是否等同于 loadout 槽。
- 经脉槽代表主动技法、被动运功、架势包，还是资源修正。
- 精修是否占用经脉容量。
- 旁修深度是否制造不同类型的槽位压力。
- 装备和可见道具是否占用构筑预算。

需要产出的设计：

- 先决定经脉槽是否是独立系统。
- 如果是独立系统，先定义用途，再定义数量。
- 不要用经脉槽补丁解决本应由流派设计解决的平衡问题。

## 主动技能 / 反应经济

当前基线描述了许多动作，但还没有定义战斗行动经济。

仍未解决：

- 角色能携带多少主动动作、反应、反制和被动触发。
- 传承是提供固定动作，还是改造主修动作。
- 旁修入口是动作、标签、触发器，还是小包。
- 音律打断、奇门拆解、影踪揭示、射艺视线否定等 counterplay 如何落到回合内。
- 2-4 回合价值如何机械化衡量。

需要产出的设计：

- 共享行动词汇。
- 反应 / 反制窗口模型。
- 区分表现标签与真实战斗动作的方法。

## 装备与可见道具归属

当前边界规定：可见道具必须先选主轴归属，再谈接口。

仍未解决：

- 武器是纯外观、携带槽、技法载体，还是数值装备。
- 软兵、伞、扇、拂尘、手杖、弓、飞刀、飞针、乐器、机关、符器如何映射到流派。
- 如何防止一件道具承载多套主循环。
- 装备是否能推荐 build，但不锁死 build。

需要产出的设计：

- 道具归属规则。
- hybrid 道具声明主循环归属的方法。
- 道具何时只是表现标签的规则。

## 出身 / 身份系统

出身与身份当前暂缓。它们不能解决当前战斗构筑缺口。

未来可能范围：

- 社会身份、势力关系、声望和开局资源。
- 对话与世界反应。
- 推荐构筑包。
- 剧情钩子和身份冲突。

硬边界：

- 出身不能锁定唯一战斗职业。
- 身份不能提供不可替代的战斗特权。
- 身份不能成为隐藏必选税。

## 同伴 / 召物 / 傀儡系统

当前基线明确阻断独立战斗同伴和独立战斗傀儡。

暂缓案例：

- 鹰、犬、兽、灵兽等同伴参与侦查、夹击、攻击、承伤、触发资源或占用行动经济。
- 傀儡、机关偶、尸偶、牵丝木人等单位独立移动、占格、承伤、接力触发或共享回合。

当前允许案例：

- 外观或叙事同伴。
- 没有战斗机制的侦查氛围。
- 静态傀儡、诱饵、一次性陷阱载体或 NPC 演出道具。
- 不增加独立行动经济的器具载体。

未来需要产出的设计：

- 决定同伴 / 召物是否进入范围。
- 如果进入，定义行动经济、耐久、反制、资源钩子和构筑成本。
- 不要把它们回填进射艺、影踪、奇门、药师或旁修文本。

## 状态 / 伤害 / 恢复系统

当前基线提到了毒、内伤、封脉、恐惧、士气、乱拍、稳态等概念，但没有定义共享状态系统。

仍未解决：

- 伤害、内伤、毒、流血、恐惧、封脉、失衡、暴露、隐蔽、标记、乱拍分别是什么。
- 哪些状态持续多回合，哪些只持续一个触发窗口。
- 驱散、治疗、抗性和反制如何工作。
- 低魔武侠边界如何约束状态表现。

需要产出的设计：

- 小而清楚的状态词汇。
- 各状态家族的流派归属。
- 重叠规则和防止全能化规则。

## 下一阶段工作流输入

下一阶段不应重新打开整个构筑系统。它应该从 active 文档出发，选择一个待完成系统，优先是 loadout。

推荐第一目标：

1. 定义 loadout 与经脉槽的用途。
2. 用纯主修、单旁修、双旁修 build 压测。
3. 验证不会制造强制旁修税。
4. 验证不会复活职业根或身份锁。
