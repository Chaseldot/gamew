# 发现与决策：叙事资产库与网站导出管线

## 资产管线当前发现

- 分享页核心结论是：项目需要一套可版本化、可结构化、可扩展、可前端展示、可游戏实现的武侠 CRPG 叙事资产库，而不是只维护一个剧本大纲。
- 当前 `site/data.js` 已承载大量结构化数据，但它仍是手写前端模块；这会让剧情资产和展示代码耦合，后续扩写人物、任务、对话树时维护成本会升高。
- 现有站点测试已经能保护页面数量、v0.3 核心数据、4K 图片和多页面导航，适合继续作为导出管线的回归保护。

## 资产管线当前决策

- 第一阶段不建立完整 CMS，不引入外部数据库。
- 先新增 `content/12-website-assets/web_export.json` 作为网站导出源，保持 JSON 给前端读取 / 生成最直接。
- 新增 `scripts/build-site-data.mjs` 把 JSON 转成 ESM `site/data.js`，并提供 `--check` 模式用于 CI/本地测试。
- `site/data.js` 加生成标记，后续内容修改应改 JSON 或更上游资产，再运行导出脚本。
- 后续可逐步拆出 `content/characters/*.yaml`、`content/factions/*.yaml`、`content/quests/**/*.yaml`，但本轮先不把所有内容拆散，避免过度重构。

## 资产管线待验证点

- [x] `web_export.json` 是否能完整表达当前网站需要的全部 export。
- [x] 生成后的 `site/data.js` 是否和现有前端兼容。
- [x] 测试是否能发现手写改动导致的生成文件不同步。

## 资产管线验收结论

- `content/12-website-assets/web_export.json` 已成为当前网站结构化内容源。
- `scripts/build-site-data.mjs` 会校验关键字段、唯一 ID 和核心数组数量，并生成带 banner 的 `site/data.js`。
- `site/tests/content-pipeline.test.mjs` 会运行生成脚本 `--check`，能发现 `site/data.js` 与内容源不同步。
- 后续内容扩写应优先改 `web_export.json` 或更上游 Markdown/YAML，再重新生成 `site/data.js`。
