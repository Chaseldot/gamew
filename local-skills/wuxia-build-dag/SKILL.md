# Wuxia Inheritance DAG

## 用途

当任务聚焦 **24 个传承设计** 时使用本 skill。

固定前提：

- 八大流派固定，不改名、不换定位、不改核心资源；
- 传承可以重写、重命名、合并、拆分或替换；
- 当前等级基线采用 9 级里程碑；
- 武侠幻想来自 `$wuxia-fantasy-suite` 维护的固定测试集；
- 本轮目标是玩法蓝图层，不写数值技能包。

## 不做什么

本 skill 不处理：

- loadout；
- 经脉槽；
- 运功位；
- 装备矩阵；
- 出身 / 身份系统；
- 同伴 / 傀儡独立战斗系统；
- 剧情章节或势力；
- 具体数值技能。

如果这些内容出现，只能作为“当前不处理”的边界，不进入本轮设计。

## 最小产物

| 产物 | 必须包含 |
|---|---|
| 八流派设计包 | 每个固定流派各 1 份，包含该流派能力主权、3 个传承的定位与名称、差异化说明、旁修派生参考。 |
| 24 传承矩阵 / 蓝图 | 流派、传承类型、传承名、CRPG 定位、核心幻想、核心循环、资源关系、3/5/7/8/9 级落点、旁修参考接口、边界。 |
| 审计报告 | 八团队设计汇总、24 传承状态、幻想测试覆盖、CRPG 定位健康、P0-P3 问题、审计建议、用户待拍板项。 |

## 主线程与子 agent

主线程承担 **总控 / 编排者**，不是子 agent。

| 角色 | 是否子 agent | 职责 |
|---|---:|---|
| 总控 / 编排者 | 否 | 读文档、控范围、发任务、结构 lint、合并审计、写报告、接收用户建议、分发下一轮返修 |
| 八流派设计师 | 是 | 游锋、破军、拳掌、射艺、影踪、药师、音律、奇门各 1 个 agent，只设计自己流派的 3 个传承 |
| 武侠幻想测试审计 | 是 | 用固定幻想测试集检查覆盖，不新增机制 |
| CRPG 战斗健康审计 | 是 | 检查定位、循环、反制、队伍职责和系统健康 |
| 武侠文案润色师 | 是 | 机制过审后统一命名、语气和武侠表达 |

不再使用“武侠迷 agent”。幻想生产、提炼、CRUD 由 `$wuxia-fantasy-suite` 负责；本 skill 只消费固定测试集。

## DAG

```text
总控：读取 active 文档，生成任务包
  ↓
总控：结构预检
  - 八流派固定
  - 9 级里程碑
  - 幻想测试集可读
  - 不碰 loadout / 经脉 / 数值技能
  ↓
并行设计：八流派设计师各自产出本流派 3 传承草案
  ├─ 游锋设计师：只设计游锋，以缠斗 / 锋势为能力主权
  ├─ 破军设计师：只设计破军，以阵线 / 冲势为能力主权
  ├─ 拳掌设计师：只设计拳掌，以制身 / 经脉破绽为能力主权
  ├─ 射艺设计师：只设计射艺，以射线 / 准星为能力主权
  ├─ 影踪设计师：只设计影踪，以藏形 / 藏机为能力主权
  ├─ 药师设计师：只设计药师，以药性 / 药性资源为能力主权
  ├─ 音律设计师：只设计音律，以节奏 / 节拍为能力主权
  └─ 奇门设计师：只设计奇门，以布局 / 阵机为能力主权
  ↓
总控：合并八份草案并做结构 lint
  - 是否 8×3=24
  - 是否每条都有 3 / 5 / 7 / 8 / 9 级职责
  - 是否每个流派只从本流派能力长出
  - 是否同流派 3 个传承差异化清楚
  - 是否每个流派都有旁修派生参考
  - 是否越界
  ↓
并行审计
  ├─ 武侠幻想测试审计
  └─ CRPG 战斗健康审计
  ↓
总控：汇总八团队设计、审计问题、审计建议
  ↓
武侠文案润色师：只润色名称和表达，不改机制 verdict
  ↓
总控：向用户报告
  - 八个团队各自的 3 传承定位与名称
  - 审计层发现的问题与建议
  - 需要用户给建议 / 拍板的分歧
  ↓
用户给出建议
  ↓
总控：把用户建议合并成八个流派返修任务包
  ↓
八流派设计师定向返修各自流派
  ↓
原审计 agent 定向复审
  ↓
总控：输出下一版报告，继续等待用户建议
```

## 总控结构 lint

在审计前总控必须先检查：

| 检查项 | 失败处理 |
|---|---|
| 是否正好 24 个传承 | P0，退回设计师 |
| 是否每个流派正好 3 个传承 | P0，退回设计师 |
| 是否改动八大流派定位 / 核心资源 | P0，退回设计师 |
| 是否兼容 9 级里程碑 | P0/P1，退回设计师 |
| 某流派传承靠其他流派核心能力成立 | P1，退回对应流派设计师 |
| 同流派 3 个传承缺少差异化 | P1，退回对应流派设计师 |
| 是否写入 loadout / 经脉 / 数值技能 | P1，删去或退回设计师 |
| 是否每条有 9 级终局方向 | P0/P1，退回设计师 |
| 是否缺少旁修派生参考 | P2，进报告或退回补充 |

## 设计字段

每个传承至少写清：

| 字段 | 说明 |
|---|---|
| 所属流派 | 八大固定流派之一。 |
| 传承类型 | 如连段压制、破招反制、蓄势爆发、护线防守、毒性运营。 |
| 推荐传承名 | 可有备选名，但必须给推荐名。 |
| CRPG 战斗定位 | 队伍中承担什么功能。 |
| 核心幻想 | 玩家选择该传承时想体验什么。 |
| 核心循环 | 起手、推进、收束。 |
| 资源关系 | 如何使用本流派核心资源。 |
| 3 级初阶方向 | 选择传承时获得什么玩法身份。 |
| 5 / 7 / 8 中阶方向 | 中级技或成长节点服务什么。 |
| 9 级终局方向 | 传承高级技 / 终局能力的蓝图。 |
| 旁修参考接口 | 哪些低中阶味道可能被旁修借用。 |
| 边界 | 它不是什么，不能吞掉谁。 |

每个流派设计包还必须写清：

| 字段 | 说明 |
|---|---|
| 能力主权 | 该流派的一词能力、核心资源、解决战斗问题的介质。 |
| 三传承差异化 | 三个传承分别如何在同一能力轴内分工，不能靠偷其他流派能力区分。 |
| 旁修派生参考 | 本流派主修时旁修其他七流派可能派生出的低中阶能力；本流派可借给其他主修的低中阶味道。 |
| 禁止侵入 | 明确哪些能力属于其他流派，不能作为本流派传承核心。 |

## 条件返修

| 情况 | 处理 |
|---|---|
| P0 | 必须返修。 |
| P1 | 必须返修。 |
| P2 | 不阻断，可由设计师顺手修，或进报告等用户拍板。 |
| P3 | 交给文案润色或报告记录。 |

用户回流轮次不设上限。每次用户给出新建议，都视为新一轮输入，总控必须继续拆分任务并分发给对应流派设计师返修。

禁止的是 **无用户新输入的 agent 自循环**：审计后必须先报告给用户；不能让设计师和审计 agent 在同一轮里无限互相返修。若一轮返修后仍有 P0/P1，总控应如实报告问题和建议，等待用户下一次回流。
