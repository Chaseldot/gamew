# 质量与审计

## 质量标准

强人物原型应当：

- 一眼有清楚的武侠形象；
- 可支撑玩家构筑、NPC、队友、敌人或资产 prompt；
- 有实现者能理解的 CRPG 战斗定位；
- 表达战斗中的动作、节奏、取舍、压迫或反制；
- 低魔、傀儡、兽、毒、符纸或民俗术都保持可见、可打断、可反制；
- 不是职业、门派、场景、招式、剧情背景或著名人物换名。

## 弱输入改写

| 弱输入 | 问题 | 更好的方向 |
|---|---|---|
| `雪山守碑人` | 太泛，不够代表性。 | 改成更可识别的防守形象，例如 `护寺罗汉僧`。 |
| `斗转复国客` | 剧情 / 背景太重，战斗幻想不够清楚。 | 围绕战斗幻想改写，例如 `斗转借力客`。 |
| `巷尾短兵恶斗` | 是场景，不是人物原型。 | 提炼出可复用人物，例如 `狭巷短刀客`。 |
| `酒楼掀桌侠` | 是单次动作梗，不是稳定人物形象。 | 只有能形成稳定战斗循环时，才提炼为人物。 |

## 查重规则

新增或改名之前：

- 搜索拟定的 `形象`；
- 搜索主要参考人物，例如新增“某某式”条目前先搜 `李寻欢`；
- 搜索有辨识度的武器、媒介或战斗幻想关键词；
- 如果只是局部相似，读取附近行判断是否真重复。

遇到重复时，选择一种处理：

- 保留已有行，只建议字段修订；
- 把新想法中更强的部分合并进已有行；
- 只有战斗循环和队伍定位清楚不同，才新增一行；
- 只有用户要求表格维护时，才归档或拆分。

## 审计报告格式

批量审计时按这些组报告：

- 高质量保留项；
- 弱或泛的人物形象；
- 构筑归类牵强的条目；
- 可能重复或可合并条目；
- 建议改名、归档或降低排序的条目；
- 需要用户判断的开放问题。

审计说明要聚焦行为问题。不要把每个风格偏好都写成必须修复项。

## 常见失败模式

| 失败模式 | 修正方式 |
|---|---|
| 著名人物换名 | 提炼其战斗幻想、媒介和 CRPG 定位。 |
| 纯场景 | 找出制造或承受该场景的可复用人物。 |
| 纯职业 | 补足如何入场、压迫什么、制造什么取舍。 |
| 混合堆料 | 选一个主修，删掉对循环不必要的旁修。 |
| 魔法漂移 | 补上可见媒介、准备、代价和反制。 |
| 系统泄漏 | 标记 `待定`，或在不发明 loadout、经脉、出身、完整随从规则的前提下改写。 |
