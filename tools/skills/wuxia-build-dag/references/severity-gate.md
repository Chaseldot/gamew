# Severity Gate

## 严重度

| 级别 | 定义 | 示例 | 处理 |
|---|---|---|---|
| P0 | 最小产物不可用 | 不是 24 个传承；某流派不是 3 个传承；八流派设计包缺失；固定流派被改；9 级里程碑被破坏；幻想测试集不可读 | 必须返修 |
| P1 | 关键设计不成立 | 传承没有闭环；同流派传承边界严重重叠；同流派 3 传承缺少差异化；传承靠其他流派核心能力成立；9 级终局缺失；核心幻想无法通过构筑支持；旁修接口替代主身份；出现不可反制循环 | 必须返修 |
| P2 | 可接受风险 | 3/5/7/8 级落点还不够细；某幻想支撑偏弱；命名可能误导；旁修派生参考过薄；旁修接口需后续技能池细化 | 不阻断，进报告 |
| P3 | 文案 / 风味建议 | 名字不够武侠；描述太机械；表格可读性差；术语需要统一 | 交给文案或报告 |

## 条件返修

```text
若无 P0/P1：
    进入文案润色与报告，等待用户建议

若有 P0/P1：
    总控先把问题写入报告
    等待用户建议
    总控把用户建议合并成八个流派返修任务包
    对应流派设计师只修自己流派的 P0/P1
    原审计 agent 定向复审
```

用户回流轮次不设上限。每次用户给出新建议，都视为新一轮输入，总控必须继续拆分任务并分发给对应流派设计师返修。

禁止的是无用户新输入的 agent 自循环：审计后必须先进入 human report；一轮返修后仍有 P0/P1 时，也必须报告给用户并等待下一次回流，不继续让 agent 自动互相返修。

## 返修任务包

| 字段 | 要求 |
|---|---|
| 问题 ID | 唯一 ID，例如 CRPG-003 / WUX-004。 |
| 级别 | P0 / P1。 |
| 发现者 | 武侠幻想测试审计 / CRPG 战斗健康审计 / 总控 lint。 |
| 涉及对象 | 流派 / 传承 / 9 级终局 / 幻想测试。 |
| 问题描述 | 具体而可验证。 |
| Pass condition | 修完后怎样算通过。 |
| 禁止方案 | 不允许用什么方式修。 |
| 用户建议 | 用户对这个问题的方向性意见。 |
| 分发对象 | 游锋 / 破军 / 拳掌 / 射艺 / 影踪 / 药师 / 音律 / 奇门设计师。 |
| 是否需要 human | 是 / 否。 |

## 定向复审

只检查：

1. 原 P0/P1 是否解决；
2. 是否引入新的 P0/P1；
3. 是否仍满足“24 传承 + 固定幻想测试集审计”两个最小产物；
4. 是否仍遵守 9 级里程碑与不处理范围。

复审输出：

| 问题 ID | 原级别 | 返修结论 | 是否新增 blocker | 建议 |
